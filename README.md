# Landsat thermal calibration for river temperature monitoring — Vistula River (2000–2024)

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22970527.svg)](https://doi.org/10.5281/zenodo.22970527)

Code and data for:

> Basheer, A.; Amnuaylojaroen, T.; Ashraf, M.N.; Ptak, M. **Landsat Thermal Calibration for River Temperature Monitoring: A 25-Year Case Study of the Vistula River.** *Water* (MDPI), 2026 (under review, manuscript water-4575579).

This repository reproduces every quantitative result of the paper: the matching of Landsat 5/7/8/9 Collection 2 surface temperature with in-situ water temperature at three gauging stations of the lower Vistula (Toruń, Chełmno, Gdańsk-Świbno), the four-stage quality control, the linear calibration and its validation (ten-fold, leave-one-out, leave-one-station-out, bootstrap), the reduced-major-axis slope, the twenty-algorithm comparison, the sensor-stratified analysis, the monthly composites and coverage-controlled trends, the August 2020 anomaly and the longitudinal thermal profile.

| Key result | Value |
|---|---|
| Matched pairs (±3 days) → after quality control | 942 → 876 |
| Calibration (in-situ = 0.8125 · LST + 2.7965) | R² = 0.9104, RMSE = 1.37 °C, MAE = 1.10 °C |
| Ten-fold / leave-one-out CV | R² = 0.9102 / 0.9100 |
| Leave-one-station-out (mean of stations) | R² = 0.8963, RMSE = 1.46 °C |
| Sensors (Landsat 5, 7, 8, 9) | R² = 0.87–0.92 |
| August trend (coverage-controlled) | +1.07 °C per decade (p = 0.043) |

## Repository structure

```
code/
  gee/                        Google Earth Engine scripts (JavaScript) that produced the Landsat data
    01_Station_LST_Extraction.js     station time series (30 m buffer, QA_PIXEL water/cloud mask)
    02_Centerline_Points_Export.js   monthly composites sampled at 30 m centreline points (175 exports)
    03_Aug2020_Heatwave_Export.js    exploratory August 2020 corridor export (not used in the calibration)
  python/                     reproducible analysis pipeline (run in order, or run_all.py)
    config.py, common.py
    01_match_and_qc.py               matching (±3 d) and four-stage quality control
    02_calibration_validation.py     calibration, CV, bootstrap, RMA, station statistics, 20 algorithms
    03_loso_and_sensitivity.py       leave-one-station-out, nested QC, window sensitivity, 7-day SD
    04_sensor_attribution.py         Landsat 5/7/8/9 attribution (WRS-2 phase) and sensor statistics
    05_composites_trends_profile.py  monthly river means, trends, August 2020, longitudinal profile
    original_scripts/                scripts as originally run (Colab paths; kept for transparency)
data/
  raw/insitu_imgw/            daily water temperature and water level, May–Nov 2000–2024 (IMGW-PIB)
  raw/landsat_station/        Landsat surface temperature at the three stations (GEE script 01)
  processed/                  matched pairs (942), quality-controlled pairs (876, with sensor), monthly river means
  large/                      place the Zenodo files here (whole-river monthly composites, ~1.3 GB)
results/
  tables/                     outputs of the pipeline (JSON/CSV)
  figures/                    Figure 8 (longitudinal profile) regenerated by step 5
docs/
  data_dictionary.md          description of every data file and column
  UPLOAD_GUIDE.md             how this repository and the Zenodo dataset were published
```

## Reproducing the results

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
cd code/python
python run_all.py
```

Steps 1–4 use only the files in `data/raw` and run in a few minutes. Step 5 needs the whole-river monthly centreline composites from Zenodo (https://doi.org/10.5281/zenodo.22970527): unzip them into `data/large/` (or set the environment variable `VISTULA_LARGE_DIR`). Without them, step 5 still computes the trends and the August anomaly from `data/processed/monthly_river_mean_lst.csv`.

Results were produced with Python 3.14.6, pandas 3.0.3, NumPy 2.5.0, SciPy 1.18.0, scikit-learn 1.9.1, statsmodels and matplotlib 3.11.0; random seeds are fixed at 42. Tree-ensemble scores in the algorithm comparison can differ in the third or fourth decimal between scikit-learn versions. The published bootstrap (Supplementary Table S4) used an unseeded generator; the seeded bootstrap here agrees to within 0.003.

To regenerate the Landsat inputs, run the scripts in `code/gee/` in the Google Earth Engine Code Editor (https://code.earthengine.google.com). Script 02 needs the 30 m centreline points as an Earth Engine asset; the shapefile is included in the Zenodo record.
